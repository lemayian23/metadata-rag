# Capability 09 — Multimodal RAG

## Goal
Ingest and retrieve over non-text content (images, charts, scanned pages) using
the same vector index that already powers text retrieval — no new embedding model,
no new index.

## Core insight
We do NOT need CLIP or a multimodal embedder. We caption the image at ingest
with a local vision LLM, then embed the caption. Retrieval, reranking, filters,
and generation all work unchanged.

## Endpoint
POST /ingest/image  { image_base64, caption_hint?, metadata..., tags[] }
  -> caption generated by the vision model
  -> caption embedded via nomic-embed-text
  -> chunk stored with modality="image"

POST /query gains: modality: "text" | "image" | "table" | "page" | null

## Pipeline
  image_bytes
    -> vision.caption_image()  (moondream via Ollama)
    -> embed_texts([caption])  (nomic-embed-text, 768-d)
    -> Chunk(modality="image", content=caption, raw_content=caption)

## Vision model
Default: moondream (828 MB) — runs on 8 GB RAM alongside qwen2.5:1.5b.
Swap in llava:7b for better quality at ~4.7 GB.

## Schema
- chunks.modality TEXT NOT NULL DEFAULT 'text'
- Index: B-tree on modality.
- No BYTEA column — we store only the caption. Add asset BYTEA later if you need
  to display the original image.

## Retrieval
`retrieve_chunks(modality=...)` appends a WHERE clause. Both `/query` and the
vector/corrective branches of `/ask` pass it through.

## Trade-offs
- (+) Zero new infrastructure — same index, same reranker, same model stack.
- (+) Unified citations: an image citation has title, source, content (caption).
- (+) Works on 8 GB RAM.
- (-) Loses visual nuance. "Which chart shows a rising trend?" retrieves the
  caption text, not the chart's visual structure.
- (-) Caption quality bounds retrieval quality. moondream is small; llava:7b better.
- (-) Ingest latency: 5-30 s per image depending on model load state.

## Observed results
Ingest: 1x1 red pixel PNG -> caption "A red square image with no text or other objects."
Query "test image" with modality=image:
    returned the image chunk, score 0.58, rerank_score -8.79
Query "digital services tax" with modality=image:
    returned the same image chunk at score 0.35 (only image in DB, no min-score threshold)

## Known issues
- modality filter does not imply relevance. With rerank=false, pgvector returns
  top-K regardless of absolute score. Add min_score threshold when needed.
- Caption prompt does not extract table structure or chart data; for tables,
  a dedicated extractor is future work.
- Image bytes are discarded after captioning — no re-display.
